# ADR 0020: Ternary Bonsai 2 27B and the PrismML llama.cpp fork

Status: owner-approved migration, completed. The macOS and Windows checks are complete; see [current status](../M3_STATUS.md). This decision replaces the generation model, the image projector, and the runtime build in [ADR 0019](0019-qwen38-private-server.md). The private socket transport, the memory profiles, the context policy, the reasoning rules, and the embedding encoder from ADR 0019 stay in effect.

Use Ternary-Bonsai-2-27B `PQ2_0` (7.21 GB, 2.13 bits per weight) and its Q8_0 image projector on both platforms. Prism ML built the model from Qwen3.8-27B, so the chat template, the tool-call format, the thinking control, and the 262,144-token training context are the same. The model is Apache-2.0. The managed catalog pins each file, revision, size, and hash. Apache-2.0 redistribution requires the license text and the notice: the package ships `licenses/ternary-bonsai-2-LICENSE.txt`, `licenses/ternary-bonsai-2-NOTICE.txt` (Prism ML copyright and attribution), and `licenses/qwen3.8-LICENSE.txt` (Alibaba Cloud copyright for the base model), and the third-party notices list both packages.

Use the PrismML fork of llama.cpp, release `prism-b10709-9a9394a`, for all inference. Stock llama.cpp cannot read the `PQ2_0` tensors. The fork ships prebuilt macOS Metal, Windows CUDA 13.3, and Windows HIP archives. The manifest pins each archive hash. The Windows CUDA archive keeps the CUDA 13.3 runtime and Visual C++ dependencies from before; it no longer needs the LLVM OpenMP runtime. The fork prints the memory report lines at log verbosity 4, so the server runs at that verbosity.

Owner decision (2026-09-20): the Windows AMD backend is HIP, not Vulkan. The archive `llama-prism-b10709-9a9394a-bin-win-hip-radeon-x64.zip` carries `ggml-hip.dll`, `libhipblas.dll`, `libhipblaslt.dll`, `rocblas.dll`, and the `rocblas/library` and `hipblaslt/library` kernel data, which the package copies as directories. The backend reports devices as `ROCm0`, so device selection, the `--override-tensor` device, the `--list-devices` parsing, and the memory buffer parsing all use that name, and the AppContainer sets `HIP_VISIBLE_DEVICES`. `ggml-hip.dll` imports `amdhip64_7.dll`, which is not in the archive: the user's AMD Adrenalin driver supplies it. The compiled AMD architectures are gfx1030, gfx1031, gfx1032, gfx1100, gfx1101, gfx1102, gfx1150, gfx1151, gfx1200, and gfx1201. Intel graphics are not supported.

Take the macOS archive only from a fork build made with Xcode 26 or later. An older Apple toolchain cannot compile the Metal tensor kernels. The runtime then reports `the tensor API is not supported in this environment`, falls back to the older matrix kernels, and the prompt speed drops to about one third on Apple M5 hardware. Release `prism-b10685-7dffb15` had this fault.

Speculative decoding: Bonsai 2 ships no dspark drafter, and the GGUF file has no multi-token prediction head. The server supports n-gram self-speculation (`--spec-type ngram-mod`), which needs no extra model and no extra memory. The profile constant `speculation` selects `none` or `ngram-mod` for generation servers. The default stays `none` until the comparison in the M3 status shows a gain on the agent workload.

Owner decision (2026-09-18, revised 2026-09-22): all platforms use an FP16 context cache, and the context is fitted once, before the server starts. The rule in `fittedContextTokens` subtracts the model file size, 512 MiB of fixed server buffers, and a 512 MiB margin. It divides the remainder by the cost of one token on that backend: 66,048 bytes on CUDA and HIP, and 70,656 bytes on Metal. The FP16 cache takes 65,536 bytes on every backend; the compute buffers take 512 bytes on CUDA and 5,120 bytes on Metal, at the fixed 256-token micro-batch. It rounds down to a multiple of 4,096 and caps the result at 131,072 tokens. When the remainder cannot hold the 32,768-token minimum, the rule returns no size and the worker reports that the graphics memory is unsupported. The floor for a dedicated GPU is 10,444,171,616 bytes: 7,206,168,928 for the model, 536,870,912 for the fixed buffers, 536,870,912 for the margin, and 2,164,260,864 for the smallest context. Windows reads the memory the GPU reports as free at each model load and fits to the smaller of that value and the budget. Every number above is measured on the pinned build; see [current status](../M3_STATUS.md). The earlier 512 MiB and 2 GiB constants had no recorded calculation and are removed. The minimum Windows card is 12 GB, because the common cards have 8, 12, 16, or 32 GB, and a 10 GB card keeps too little free memory after the display takes its part. The rule replaces the fixed 32,768-token context in ADR 0019. The server still runs with no automatic fitting and no context shifting; a generation that fills the fitted context stops at the boundary, and compaction stays at 80 percent of the fitted context. Core learns the fitted size from the first worker response.

The MLX 2-bit release of the same model is a text-only Apple Silicon package with its own Python runtime. It does not run behind the private llama-server socket. It is a measurement target only: run it with the Prism demo server and pass `--url` to `pnpm model:compare`. A product decision on MLX needs a new ADR.

Owner decision (2026-09-18): sampling follows the model card's thinking-mode settings. Every chat request uses temperature 1.0, top_p 0.95, top_k 20, min_p 0, and no presence or repetition penalty; the agent definitions, the review, and compaction all set temperature 1. Greedy decoding (temperature 0) stays only for structured JSON output. The reason is that this model family repeats itself without end under greedy decoding in thinking mode, and a 2-bit model is more prone to it. As a worst-case guardrail, the generation server starts with `--reasoning-budget 32768`: the server ends the thinking after 32,768 tokens and the model then answers. This replaces "send no reasoning budget" in ADR 0019.

Owner decision (2026-09-19, revised 2026-09-23): the model card states that the `low` reasoning effort is not meaningfully supported and behaves close to `xhigh`, so the effort control offers None, Medium, and Extended only. The selected level goes to the chat template as the reasoning effort. Requests send no per-request thinking budget: a small budget ended the thinking in the middle of a sentence, and the model then continued its thinking in the answer. The 32,768-token server budget is the only thinking limit.
